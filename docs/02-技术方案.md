# 技术方案

> 读者：开发 Agent。产品负责人可以只看第一节"大白话版"。

## 0. 大白话版

手机桌面是一个叫"启动器"的 App 画出来的，别的 App 没有权限直接改它。
但安卓有一个给视障人士用的"无障碍服务"——它能**读出屏幕上有什么**（"这里有个微信图标"），
也能**替人操作**（点击、长按、拖动）。我们就借这个能力，像一个看得见屏幕的机器人一样，
一个个把图标拖进文件夹。原生安卓桌面还更进一步：它为视障用户准备了"移动图标""创建文件夹"的**语义按钮**，
我们可以直接按这些按钮，而不用真的模拟手指拖动——更快、更准。

## 1. 架构总览

```
┌──────────────────────── App 进程 ────────────────────────┐
│  MainActivity（界面）                                     │
│     │ 启动整理 / 查看预览 / 停止                            │
│     ▼                                                    │
│  Scanner ──► Classifier ──► Planner ──► Executor          │
│  扫描桌面     归类（词典）    生成步骤      执行步骤            │
│     ▲                                    │                │
│     └──────── TidyAccessibilityService ◄─┘                │
│              （读节点树 + 执行动作 + 音量键中止）             │
└──────────────────────────────────────────────────────────┘
```

| 模块 | 输入 | 输出 | 说明 |
|---|---|---|---|
| `TidyAccessibilityService` | 系统无障碍事件 | 节点树快照、动作结果 | 唯一能碰桌面的模块 |
| `LauncherReader` | 桌面窗口根节点 | `HomeSnapshot`（每页的图标/文件夹，名字+坐标+可用动作） | 只读 |
| `Classifier` | 应用名 + 包名 | 类别 | 三级规则，见第 3 节 |
| `Planner` | `HomeSnapshot` + 类别结果 | `List<Step>` | 纯函数，可单测 |
| `Executor` | `List<Step>` | 逐步执行 + 校验 | 两种驱动，见第 2 节 |

## 2. 执行引擎：两种驱动

### 2.1 语义驱动（首选）—— Launcher3 无障碍动作

原生安卓桌面（AOSP Launcher3 / Pixel Launcher）为读屏用户在图标节点上注册了自定义无障碍动作
（`LauncherAccessibilityDelegate`），其中有"移动项目"。触发后桌面进入"无障碍拖放模式"，
桌面格子和其他图标会以虚拟节点（`ExploreByTouchHelper`）出现，目标图标上会出现
"创建文件夹：X""添加到文件夹：Y""移到此处"之类的动作。

流程（建文件夹：把 A 和 B 合并）：
1. 读树，找到 A 的节点，在 `actionList` 中找标签含"移动"/"Move"的动作，`performAction`。
2. 等待 `EXECUTE_SETTLE_MS`，重新读树。
3. 找到 B 对应的节点（虚拟节点），在其 `actionList` 中找标签含"创建文件夹"/"Create folder"的动作并执行。
4. 重新读树，校验：A、B 消失，出现一个文件夹节点。

> ⚠️ 以上动作的确切标签文字、虚拟节点结构**来自对 Launcher3 源码的了解，尚未在产品负责人的手机上验证**。
> 阶段 0 探针的首要任务就是导出真实节点树和动作列表来确认。匹配标签时必须同时兼容中英文，
> 并且以"导出的真实标签"为准更新常量。

优点：不依赖坐标和手速，不会误触翻页，每步 <1 秒。

### 2.2 手势驱动（兜底）—— 模拟手指拖动

当语义动作不存在时使用。`dispatchGesture` + `StrokeDescription(willContinue = true)` 分三段：
1. 按下 A 中心并保持 `LONG_PRESS_MS`（估计 700ms）→ 桌面进入拖动态
2. 从 A 平滑移动到 B 中心，用时 `DRAG_MOVE_MS`（估计 400ms）
3. 在 B 上停留 `HOVER_BEFORE_DROP_MS`（估计 600ms，桌面需要悬停才会判定"合成文件夹"）后松手

跨页：拖到屏幕左/右边缘停留 `EDGE_HOLD_MS` 触发翻页。

缺点：时序参数需要真机调；易受用户误触干扰。

### 2.3 每一步都"读 → 做 → 验"

桌面在每次移动后会重排，旧坐标/旧节点立即失效。所以 Executor 的每一步：
```
重新读树 → 按名字重新定位目标 → 执行 → 等待 → 再读树校验 → 成功/重试1次/跳过并记录
```
绝不缓存节点或坐标跨步骤使用。

### 2.4 中止

服务开启 `flagRequestFilterKeyEvents`，执行期间任一音量键按下 → 立即停止后续步骤并提示。
执行期间显示一个**不可触摸**的悬浮提示层（`TYPE_ACCESSIBILITY_OVERLAY` + `FLAG_NOT_TOUCHABLE`），
显示进度与"按音量键停止"。必须不可触摸，否则会拦截我们自己注入的手势（见 ADR-005）。

## 3. 归类：三级规则（不用大模型）

1. **包名词典**（`assets/categories.json`）：常见应用的包名 → 类别。命中即定。
2. **包名/应用名关键词**：如包名含 `bank`、应用名含"银行" → 金融。
3. **系统字段** `ApplicationInfo.category`（API 26+，很多应用未填写）→ 映射到我们的类别。
4. 都不命中 → "其他"。预览时用户可手动改。

类别（第一版固定 9 类）：社交、购物、影音、学习办公、出行、金融、生活服务、游戏、工具，外加兜底"其他"。
类别少于 2 个图标的不建文件夹，留在原地。

## 4. Planner 规则

- 只处理桌面工作区里的**应用图标**；已存在的文件夹不拆（第一版）。
- 每个类别：取该类第一个图标作为"锚点"，后续图标依次合并到锚点所在文件夹。
- 文件夹建成后重命名为类别名（打开文件夹 → 名称输入框 `ACTION_SET_TEXT`）。阶段 1 再做。
- 输出 `Step` 列表供预览展示和 Executor 执行。

## 6. 阶段 2 模块划分（界面先行，见 ADR-010）

| 包 | 内容 | 负责 |
|---|---|---|
| `classify/` | `Classifier.kt` 接口（Opus 定稿）+ 实现 + 单元测试 | 分类器任务卡 |
| `ui/` | 主题色、lucide 矢量图标、聚焦引导、各页面 | 界面任务卡 |
| `data/` | `AppRepository`：用 PackageManager 列出带桌面入口的应用（名字、包名、图标、系统 category） | 界面任务卡 |
| `probe/` | 阶段 0 探针，保留，从首页隐藏入口进入 | 不动 |

数据来源说明：**真正的整理对象是"桌面上的图标"**，要靠无障碍读取（依赖探针结论）。界面先行阶段，扫描页暂用
PackageManager 的应用列表顶替，接口留成 `AppRepository.loadApps()`，执行引擎就绪后换成桌面快照。

页面（对应原型 `design/一键理桌原型-v1.html`）：首页（含三步聚焦引导）→ 权限引导 → 扫描 → 分类预览（改分类 / 整类跳过）
→ 开始前确认 → 整理中（悬浮进度条，执行引擎就绪后接入）→ 完成。

## 7. 阶段 1 整理引擎（engine/，接口见 Engine.kt）

依据 2026-10-24 ColorOS 16 真机实测（ADR-013、014）。

### 7.1 读桌面（DesktopReader）
- 回桌面：`performGlobalAction(HOME)`，等 1.5s，找 title=系统桌面 / 包名=默认桌面的窗口（沿用探针的重试）。
- 结构（ColorOS 实测）：`id/workspace`（ScrollView）的每个子节点是一页，页 → 一层容器 → 图标。
  当前页的页节点 `isVisibleToUser=true`，其他页为 false，但图标仍在树里（坐标无效）。
- 应用图标：TextView，`text` = 应用名（desc 可能带"有 N 条通知"，不要用）。
  文件夹：FrameLayout，desc = `文件夹：<名字>`。小组件（类名含 AppWidgetHostView）跳过。`id/hotseat` 下的跳过。
- 读完回到 App（`startActivity(MainActivity, NEW_TASK | REORDER_TO_FRONT)`）。

### 7.2 规划（Planner，纯函数，JVM 单测）
输入 `DesktopSnapshot` + `TidyRequest`，输出有序步骤：
- 每个类别找"目的地"：① 桌面上有**与类别同名**的已有文件夹 → 用它（不改名）；② 否则选该类应用最多的那一页上的第一个应用作锚点（新建，之后改名）。
- 其余同类应用依次拖到目的地。**先处理和目的地同页的，再处理跨页的**，跨页按页距由近到远。
- 已有文件夹本身不移动、不拆（PRD 第 5 节）。应用名在桌面上重名时只处理第一个，其余记为失败。

### 7.3 执行（GestureExecutor）
每一步都是"读 → 定位 → 拖 → 读 → 校验"，绝不复用旧坐标：
1. 若 A 不在当前页：翻页到 A 所在页（横向滑动手势 250ms，每翻一页重读确认页码，最多重试 2 次）。
2. 瞄准点 = 节点范围水平中心，纵向 `top + 0.48 × 高`（图案中心，实测）。
3. 同页拖动：按住 1000ms（willContinue）→ 800ms 移到目标图案中心 → 悬停 900ms 后松手（实测参数）。
4. 跨页拖动：按住 1000ms → 400ms 移到屏幕边缘（目标在后面的页拖到右边缘，反之左边缘）→ 每需翻一页在边缘停 `EDGE_HOLD_MS`（估计 1000ms，**待实测**）→ 移回目标图案中心（坐标用读取时记下的目标页位置）→ 悬停 900ms → 松手。
5. 校验：A 不再作为独立图标出现，且目的地是文件夹 → 成功。否则重试 1 次（重新读树、重新定位），仍失败记入 failedApps 继续下一个。跨页拖动失败落到中间页的，下一轮会被重新定位，自然纠正。
6. 新建文件夹后改名：轻点文件夹打开 → 读树找标题（text="文件夹"、可点）→ 点它 → 对 EditText 做 `ACTION_SET_TEXT` → 返回键收起键盘并关闭文件夹 → 读树校验 desc 是否变成 `文件夹：<类别名>`。**未实测**，失败记入 renameFailed，不影响后续。
7. 每步前检查中止（音量键 / abort()）；执行期间挂载 `ui.ProgressPill`（`TYPE_ACCESSIBILITY_OVERLAY` + `FLAG_NOT_TOUCHABLE`），结束移除。
8. 结束：回到 App，回调 `EngineResult`。

### 7.4 干扰检测
`Settings.Secure.ENABLED_ACCESSIBILITY_SERVICES` 里除本应用外的服务（实测谷歌"开关控制"会弹向导抢前台、干扰节点读取）→ 界面在扫描前提示用户关闭。

## 8. 已知风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 产品负责人手机的桌面不暴露语义动作 | 失去首选驱动 | 退回手势驱动；阶段 0 验证 |
| Android 13+ 侧载 App 的无障碍开关被"受限设置"锁住 | 用户打不开权限 | 真机测试指南写清解锁步骤；优先 adb 安装 |
| 桌面节点树没有图标节点（自绘界面） | 两种驱动都失效 | 原生 Launcher3 不会出现；其他桌面需截图识别，不在第一版范围 |
| 执行中用户触屏 | 手势被打断 | 悬浮提示 + 音量键中止 + 每步校验 |
